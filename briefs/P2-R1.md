# Brief P2-R1: Phase 2, Round 1 (user panel, Director, gateway, website; local stub backend)

Branch: start from `claude/p2-0-config` (P2-0 is done: `src/platform-config`, `docs/PLATFORM-CONFIG.md`, D-348, P20-001..008).
Authority: AGENTS.md, docs/PROCESS.md, this brief. Read `docs/PLATFORM-CONFIG.md` and `docs/EDITOR-OWNERSHIP.md` first.
Design reference (a CONCEPT, not final): the "User Panel Design" canvas, 10 screens: Home, Styles, Brief Room, Director, Plan card, Live Build, Editor reveal, Studio Tool Voice, Projects, Credits and Plan. Layout, fields and numbers there are samples.

## Owner rules for this round (1 Nov 2026)

1. **Config-first.** Nothing the user sees or the AI may do is fixed in code: Brief fields, interview questions, Styles, plans, limits, credit costs, models, providers, Director rulebook (scope, refusals, tool allow-list, what is revealed), site content, brand name/logo/colours. Extend the Platform Config; do not hard-code. Admin (a later round) only edits this config.
2. **No keys, no network to third parties.** Every key is a placeholder. Real providers, Supabase live and payments are NOT in this round. Everything must run and be tested offline with a mock.
3. **Quality never drops.** Anything AI writes is validated before the user or the editor sees it; invalid output is repaired once, then refused with a clear message.
4. **Editor stays as it is.** Nothing in the editor changes behaviour. The editor bundle check must keep passing; panel and website code must not enter the editor bundle (and the reverse).

## Slices (do in order; commit per slice)

**R1-0 Integrate.** Bring `claude/phase1-library` (Supabase client `src/cloud`, `supabase/` migrations, owner app, `@supabase/supabase-js`) and `claude/fix-7-dev` (FX10/FX11) together on this branch (merge or cherry-pick; the clone may be shallow, so fetch what you need). Resolve conflicts keeping both. Run `npm run check`. Record how you did it in the report. Schema 9 stays.

**R1-1 Config: models and payments.** Extend `src/platform-config` (the schema is unreleased, so edit version 1 in place and update tests):

- `providers[]`: id, adapter kind (`anthropic`, `openai`, `google`, `xai`, `openai-compatible`, `mock`), enabled, `keyRef` (the NAME of a server secret, never the key), base URL optional.
- `models[]`: id, providerId, kind (`text`, `image`, `video`, `voice`, `music`, `stt`), display name, tier (`fast`/`balanced`/`best`), capabilities (json, tools, vision), context size, price (input/output per million tokens, or per image / per second / per minute, in USD), `creditMargin` multiplier, roles it may serve (`director-plan`, `interview`, `write`, `studio-*`), plan gating, enabled, `recommendedForDirector`, `tested`.
- `creditRate`: credits per USD of provider cost.
- `payments[]`: provider ids with enabled, countries, currencies (adapter interface only; mock provider).
- Studios point to model roles. Tests: validation errors, gating, lookups.

**R1-2 Gateway core (`src/gateway`, pure, no DOM).** Interfaces and logic only:

- `ProviderAdapter` (`estimate`, `call`, `parse`), `MockAdapter` (deterministic, with latency and failure modes), request builders/parsers for anthropic/openai/google/xai tested on recorded fixture JSON only (no network; mark `tested:false`).
- Cost: `estimate(model, workload)` returns min/max credits; workload comes from brief size, scenes and duration.
- Credits ledger (append-only: grant, reserve, settle, refund, adjust; idempotency key; balance derived). `reserve` at the plan's maximum, `settle` at actual, difference refunded; any failure refunds in full.
- Checks before every call: model enabled, plan allows, tool on the Director allow-list (`toolDecision`), plan limits (exports, storage, clones), budget caps, rate limit. Usage log.
- Local stub store (browser) behind a `LedgerStore` interface so Round 2 swaps in Supabase. Enforcement lives in this module so the server can reuse it unchanged.

**R1-3 Panel shell.** A separate entry (not the editor bundle), same UI stack and design tokens as the editor (no React unless a decision is recorded), English and Hindi, dark theme. Sidebar, top bar with credits, route handling, empty/loading/error states. Login screens (sign up, log in, reset) over the existing `CloudBackend` with the local stub; no guest mode: the panel and editor open only after login. Unauthenticated users see only the website.

**R1-4 Home, Styles, Brief Room.** All three render from config: Style cards (enabled, gated by plan, price hint), Brief form from `styles[].brief.fields` using `src/platform-config/form.ts` (field types, show-if, validation, brief strength, estimated cost). Drafts autosave.

**R1-5 Director (mock brain), Plan card, Live Build.**

- Chat UI driven by `interview` rules from config: skip answered, cap, free text, "creative upgrade" suggestion from the rulebook text. Out-of-scope requests get the owner's `refusals` reply, not model text.
- `Planner` interface with a deterministic mock that turns a Brief into a valid Plan v3 (use the existing video-plan types and validator; a Style playbook decides scene methods in `director.methodOrder`). A real LLM planner plugs in later via the gateway.
- Plan card: scenes with method, swap control (cheaper/richer), per-scene and total credits for the chosen model, balance, shortage message, Approve (reserve) / Cancel. Model picker (Fast/Balanced/Best or exact model, per `reveal`).
- Live Build: progress steps, preview, refund on failure; "Open in editor" builds the project through the existing composition/video-plan builder as an editable project (no flat video). Library item states follow D-347.

**R1-6 Studio Tools + Asset Library.** Write, Voice, Audio, Images, Video, Captions, Thumbnail, YouTube pack as screens generated from `studios` config, each calling the gateway (mock provider), cost shown before, result saved to the project-wise Asset Library (D-347 import rule). Voice includes the clone consent tick.

**R1-7 Projects, Brand Kit, Credits and Plan, Settings, Learn.** Projects replace the File menu's New/Open/Open example (the File menu keeps them until the owner removes them). Credits and Plan from config: plan cards, what things cost, history from the ledger, top up through the mock payment provider, INR/USD switch. Brand Kit saves colours, fonts, logo. Settings: profile, language, theme. Learn: static list from config.

**R1-8 Website.** Landing, pricing, showcase from `site` config; login/sign-up calls. No live demo, no guest editor.

**R1-9 Close.** Ledger rows `P2R1-xxx`, e2e for every user-visible behaviour (real browser, ID in the title), unit tests for gateway/config, docs (`docs/PANEL.md`, `docs/GATEWAY.md`), D-349+ decisions, STATUS, CHANGELOG, `reports/P2-R1.md` with an owner try-it script (the Circumference flow end to end: log in, Story Explainer, brief, Director, plan card with credits, approve, build, open in editor, export).

## Out of scope (record, do not build)

Supabase live connection and RLS run, real Claude/OpenAI/Gemini/Grok calls, real TTS/image/video providers, real payments, the Admin app, select-and-edit, MCP/plugin. Keep every one behind its interface with a clear "not connected" state.

## Stop rules

Stop and report if: schema 9 must change; the two branches cannot be integrated without losing behaviour; the editor bundle would grow; two authoritative docs conflict. Everything else: decide, record, continue.
