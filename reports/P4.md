## 1. Summary

Five parts, built in order, tested by the owner only at the end.

## 7. Not tested, known gaps, risks

- Nothing ran against a live provider, Supabase, Razorpay or Stripe. The SQL migrations (storage limit trigger and the earlier ones) were not run on a real Supabase.
- The Studio fields are samples. A model-driven Studio run does not refresh the library inline.
- A Director pause is kept in this browser only. The panel does not list cloud-only projects made on another computer. Themes are not synced.
- The admin UI is in English except the tab names. Ready-made Styles are created only through the raw Platform Config. The "Stock and offline engines" screen is informational.
- Razorpay subscriptions need plan ids that are not mapped yet.
- Security: the tests cover the listed attacks. This is hardening, not a guarantee against every attack.
- LAY-013, LAY-014 and the four DEV-012 visual baselines pass in this sandbox but were red in CI; their CI cause was not reproduced.
