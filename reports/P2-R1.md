# Report: Phase 2 round 1, user panel, Director, gateway and website on the local stub (2026-11-01)

## 1. Summary

You can now open a website, sign up, and use a user panel: pick a Style, fill the Brief, talk to Director, see the cost of every scene before anything is made, approve, watch the video being built, and open it in the editor as normal editable scenes. Studio tools, an Asset Library per project, Projects, Credits & Plan (with a test top up), Brand Kit, Settings and Learn are there too, in English and Hindi. The editor now opens only after logging in.

Everything runs offline on a test ("mock") model. Real AI models, Supabase accounts and real payments are not connected: no keys and no outside network this round (owner rule 2). Their code is written behind interfaces and says "not connected" when used.

## How the Phase 1 cloud was integrated

- `claude/phase2-r1` starts from `claude/p2-0-config`, which already holds FX10, FX11, the newer owner app and the newer library-client.
- `claude/phase1-library` was **not merged**: a merge would have brought back its older owner app and library-client over the newer ones. Instead only the cloud files it has and this branch lacked were taken by path (`git checkout origin/claude/phase1-library -- <paths>`): `src/cloud/` (the `CloudBackend` interface and the Supabase backend), `src/ui/cloud-ui.ts`, `supabase/` (config, the projects/media and training-records migrations, the SQL policy tests), `scripts/cloud-sql-test.mjs`, `e2e/cloud-fake.ts`, the `cloud:start`, `cloud:stop` and `cloud:test` scripts, `@supabase/supabase-js` 2.117.3 and its 42 `cloud.*` strings in English and Hindi (D-349).
- The editor does **not** mount the Phase 1 account slot: the account belongs to the user panel now (docs/EDITOR-OWNERSHIP.md; owner rule 5). `cloud-ui.ts` stays unmounted, and its browser test (`e2e/phase1-cloud.spec.ts`) was not brought over.
- True state of the Phase 1 cloud: it has **never run against a real Supabase server**. What ran: the SQL policy tests on a throwaway PostgreSQL 16 with stand-ins for Supabase's `auth` and `storage` schemas (`npm run cloud:test`: "policy tests passed" again in this round), and, in Phase 1, the editor against a stand-in HTTP API. `supabase start` cannot pull its images in this sandbox (D-327).

## 5. Deviations from the brief

- The panel and website are vanilla TypeScript, not React (the editor's own panels are vanilla DOM, D-053); recorded in D-352 as the brief asks.
- Planning a draft is not charged; the charged step is the build, whose maximum the Plan card shows before Approve (D-353). The brief does not say whether the planning call itself costs credits; charging only after the person approves follows rule 3 most closely.
- "Open in editor" uses the editor's own AI importer (its Build video), pressed automatically, rather than a second builder in the panel, so the D-347 AI card and its build states stay exactly as for a pasted plan.

## 7. Not tested, known gaps, risks

- Real providers, Supabase, real payments: not tested anywhere (BLOCKED above). The provider fixtures were written by hand in each provider's documented shape, not captured from live calls.
- Exports per month are not counted (the editor does not report exports to the panel yet); the usage table shows 0. The gateway's export-limit check itself is unit-tested.
- In local mode every signed-in person of one browser sees that browser's projects (owner-only projects come with Supabase).
- AI image and AI video scenes (Pro): the build charges for them and the mock image model runs, but the editor's builder looks for the media by intent and, offline, leaves a "needs asset" frame. Not tested in a browser.
- The phone layout of the panel (one CSS breakpoint) and the light theme were not checked by eye; the light theme switch itself is tested.
- Logo upload in Brand Kit and the 200 KB limit are not covered by a test.
- The panel page loads the editor's shared core and plan-validator chunk (about 4 MB, cached by the editor too) because it validates plans and reads the Projects library.
- Hindi: every panel string has a Hindi text (unit-tested); only the Home, sidebar and credits pill were checked in Hindi in the browser.
